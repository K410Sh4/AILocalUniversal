# Registro de ativos originais do projeto

Este registro organiza as famílias de materiais originais cobertas pelo aviso de propriedade intelectual do AILocal Universal. A presença na lista não afirma que todos os componentes estejam concluídos; ela indica que as expressões originais implementadas ou documentadas no repositório são tratadas como materiais proprietários, respeitadas as exclusões de terceiros.

| Família | Ativos originais abrangidos quando presentes no repositório | Estado conhecido |
|---|---|---|
| AILocal Universal Desktop | Janela, views, diálogos, integrações, armazenamento, configuração e experiência de usuário original | Implementação ativa |
| Cognitive Pipeline | Input Processing, Semantic Analysis, Capability Vectorizer, Task Decomposer, Cognitive Planner, Orchestrator | Implementação ativa |
| Cognitive Execution | CognitiveTask, Deterministic Tools, Cognitive Task Executor, Validation Layer, Execution Trace e Inspector | Implementação ativa |
| NeuralMap | Graph Model, editor/canvas, runtime, handlers, validação, package I/O e schemas | Implementação em branch de desenvolvimento |
| NeuralPlugin | Taxonomia, arquitetura, contratos e proposta do NeuralPlugin Manager | Documentação de proposta |
| NeuralInjector / NIP | Especificação NIP 0.1.0, manifesto, estrutura ZIP, schema, checksums, pacote .neuralinjector e seus leitores/escritores quando codificados | Proposta e implementação em branches dedicadas |
| Adaptive Resource Management | Perfis de hardware, orçamentos, políticas e scheduler originais quando codificados | Roadmap / parcialmente documentado |
| Swarm / P2P | Contratos, identidade, autorização, protocolos e execução cooperativa originais quando codificados | Roadmap / arquitetura |
| Documentação e schemas | Texto técnico, diagramas, exemplos, testes e formatos originais | Evolução contínua |

## Limites de titularidade

- Código e documentação de terceiros não são reivindicados como originais do projeto.
- Um nome de componente neste registro não concede direitos exclusivos sobre uma ideia abstrata ou método em si.
- Dados de usuário, documentos, conversas, workflows criados pelo usuário e conteúdo de plugins externos não passam a ser propriedade do projeto por serem processados pela aplicação.
- Cada distribuição de plugin e pacote deve declarar sua própria licença e origem.
- O registro de software no INPI, registro de marca e eventual patente são procedimentos separados; nenhum deles foi requerido por este arquivo.
